net-utils TO-DO: identity, auth, tv suite  (rewritten around the goals 2026-11-10)
==================================================================================

One plan, shared phase numbers across three parts:
  identity   who-is-who list of logins, no secrets (~/.config/identities; command: identity)
  auth       the secrets: gpg vault on cpbee (command: auth)
  tv suite   tvmail, tvchat, tvcal, tvcontacts, Floyd (TUIs repo; it keeps its own TO-DO)
Everything is committed on main.  Two commits (USAGE.md, auth set fix) are NOT PUSHED.

GOALS (Chris, 2026-11-10)
  G1  Fewer places passwords are stored, rendered copies included.
  G2  Shims or API calls wherever a tool uses a password (ssh/scp, telnet/ftp, tv suite, sudo/su ...), not files.  # allowlist secret
  G3  Cron / Scheduled Tasks can use it with no user input.
  G4  Minimal syncing headaches.
  Overall: easier and simpler than the status quo.

DESIGN (what follows from the goals)
  1. ONE copy: the vault on cpbee.  Machines FETCH on demand (`ssh cpbee auth ...`); they do not keep copies.
     Rendering files stays only as a fallback for tools that can read nothing else, and then into tmpfs
     ($XDG_RUNTIME_DIR, mode 600, gone at logout/reboot), never as a persistent file.  Nothing persistent means
     nothing to sync (G1, G4).
  2. TWO TIERS (G3):  master tier = passphrase, `auth unlock` about once a day, for people and interactive use.
     service tier = records tagged `service`, in a second file encrypted to a key WITHOUT a passphrase.  Each
     machine or job gets its own ssh key, restricted (forced command in authorized_keys) to `auth get` of the
     records it is allowed.  Trade-off accepted by Chris 2026-11-10: service secrets are protected by file
     permissions and ssh restrictions on cpbee, not by a passphrase; this is how ~/user_bash/Foo_Bar.bash and
     friends work today.  Put in it only what a job truly needs; personal passwords stay in the master tier.
  3. A SHIM PER CLASS OF TOOL (G2):
       ssh, scp, git      SSH_ASKPASS / git credential helper -> auth get (real ssh keys stay keys)
       ftp, telnet        wrapper that fetches the password and passes it in (short-lived netrc as fallback)
       tv suite           `password_cmd = auth get ...` in each app's config (the msmtp / mbsync pattern); the old
                          file lookup stays as the fallback; every app still runs alone
       sudo, su           SUDO_ASKPASS.  UAC is not scriptable safely: out of scope.
       TOTP               auth totp (works)
       Windows Scheduled Tasks and cron   a service ssh key + `auth get`
  4. cpbee down = nothing can fetch.  Accepted; no local cache (it would work against G1).  The vault key is
     backed up off-site.

Facts worth remembering
  - Vault: ~/.local/share/auth/vault.gpg on cpbee, gpg key auth-vault; `ssh -t cpbee auth unlock` once per 8 h.
    The secret key is backed up off-site (Chris, 2026-11-04).
  - Mailutils reads `#` in a netrc as a word, so the rendered ~/.netrc has no marker lines; the tickets file may.
  - tvmail asks for imap://, so the vault record carries imap, imaps, smtp and smtps; each is rendered under
    cpbee.cmnet and bare cpbee.  The apps match the host exactly as their own config spells it.
  - Radicale is a separate login from the cpbee account.
  - The pre-commit scan flags URL-shaped examples and netrc-like lines: tag them `# allowlist secret`.
  - The webterm change (web services moved to a no-login system user) does not touch the vault or its gpg agent.
